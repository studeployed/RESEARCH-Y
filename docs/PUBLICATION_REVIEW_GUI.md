## Delivered interface

An experimental **local-only** researcher's two-source review process builds on PR71's displayed provenance, not a new matching engine:

1. Explicitly open the original source detail for a provisional publication. Select **one exact retrieval** for comparison. Open a second source detail on the **same current results page** and select its exact retrieval. The trusted host verifies that both selections belong to that displayed, current-run read model. A failed/stale selection cannot open an arbitrary source, run or local file.
2. The existing `publication_candidates._view` and `publication_match_evidence` calculate deterministic candidate comparison status. The new `publication_review_gui` service returns only permitted citation-field values and comparison outcomes, source provenance, previous decision **receipts**, and full current machine-generated warnings (including possible abstract/container DOI scope). No abstract body, licensed raw payload, cloud inference or provider request is exposed. The last 10 historical decision summaries are displayed with the older-receipts count; the complete original audit history remains in SQLite.
3. To commit, the researcher must enter an actor and specific evidence/rationale, acknowledge **all** visible warnings and press a separate **CONFIRM MATCH** (specifying which single retrieval to move to the other current identity) or **CONFIRM NOT SAME PUBLICATION** (no retrieval moved). The trusted worker verifies the complete current run SHA-256 and the exact canonical candidate revision and rebuilds the candidate comparison in the existing `decide_candidate` atomic SQLite transaction. The browser cannot submit an alternative comparison, warning list, source record, data path or automatic matching threshold.
4. An explicitly selected source having a **current** reversible association can separately preview its original audit event, target/restored identities and historical rationale. A separate explicit confirmation reuses `publication_identity.reverse_association` with fresh current/restored evidence revisions. It appends a reversal audit receipt and preserves every original retrieval and historical decision. A stale or older association cannot be silently reversed.
5. Confirmations are **single use**, cleared before the child executes. If the child dies or its response is missing, **do not retry**: the workflow requires fresh original source inspection. For a normal returned result, the trusted host independently re-reads the post-commit canonical run and candidate or current association receipt (including event identifier, decision, actor and reason) before reporting a durable audit success. Refresh clears stale selections and rebuilds the list.

## Scientific and security boundaries

This does **not** automatically identify all duplicate candidates: a researcher manually chooses two retrievals available on the **current page**. Equal title, DOI, PubMed identifier, journal supplement or other metadata never triggers an automatic merge. One match action moves **one selected source retrieval**, not an entire publication cluster, and keeps every source/group/run membership. Rejection does not split an already combined identity; the researcher must reverse the current applicable source association first. The original candidate engine decides whether a reversal or reassociation is permissible where chosen fields or specialist annotations exist.

The source records and query counts remain unchanged. A provisional identity is not yet certified a unique publication. `global_unique_publications=null`, `deduplication_complete=false`, `source_retrieval_verified=false`, `verified_complete=false` remain true across the UI and adapter. A previous decision's current status is not an independent external verification. Neither search eligibility, full abstract rights, exhaustive duplicate discovery nor any publication-ready master workbook is claimed.

No schema migration, added dependency, model, provider call or change to the approved broad OR search logic. Untrusted source text enters only ordinary text labels; the worker command is explicitly allowlisted and cannot accept arbitrary SQL, source queries or browser-chosen filesystem paths. The original protected abstract text is withheld even if a researcher-selected field is misleadingly named `title`; comparison fields come from the canonical citation-only projection.
