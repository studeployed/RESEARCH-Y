**Source of truth:** version-controlled `RESEARCH-Y_SPEC.md`, unchanged. **Baseline:** owner-merged PR #98 on 12 November 2026, `main` commit `ccc5fa2febf25b71c66a6a324a35cd07c7b2fd42`. This is an incremental, limited export acceptance contribution under parent #9/#37/#39 (requirements AUDIT-01, COUNT-01/05, EXPORT-01/03/04, SEC-03/04; partial AT-18/19/21/22).

## What is approved, and what is not

PR #97 records explicit researcher consent to the original selected run, its complete canonical SHA-256 count revision, a safe project-relative `.xlsx` filename and the researcher identity, in one immutable audit receipt. PR #98 creates a source-only, rights-restricted Excel workbook from that exact original revision; it commits a checksum-and-size staging receipt *before* writing the private file and a separate staged receipt *after* verifying and flushing its bytes. A missing private stage is recoverable only against the original approval/revision/digest; a corrupt stage is refused without replacing it.

**This PR adds publication only for that already explicitly authorised and successfully staged workbook.** It does not approve a new export, create a new revision, infer source completeness, convert provisional identities to deduplicated unique papers, or publish licensed bibliographic text. It provides an internal backend publication/recovery service, **not** a browser button or `ApplicationCommand`.

## Durability and no-overwrite transaction boundary

The new `src/research_y/provisional_manifest_publication.py` has three backend operations:

1. `publish_manifest_workbook(project, export_id)`: rejects missing or invalid original consent, missing/changed private stage, or stale source revision. It reads the original project with the existing strictly read-only, no-migration count gate before any writer invocation, then verifies the original run revision/denominators and every original consent and staged receipt inside the existing project-identity and writer-locked SQLite transaction. If and only if the requested visible `exports/<approved-name>.xlsx` does not already exist, it appends a source-free, hash-chained **publishing** audit event containing the original approval and staged-receipt IDs/hashes, stage bytes SHA-256/length and a unique `exports/.researchy-manifest-<UUID>-<random>.part` destination-side copy name. The transaction commits **before any output bytes are written**.
2. `resume_manifest_publication(project, export_id)`: requires an existing publishing intent; it never silently starts publication. With the same guarded writer transaction and the original source-revision gate, it verifies the independent immutable staged workbook, writes the intended destination-side copy exclusively (never overwrites or deletes), validates content hash/size and flushes it, creates the **final filename using the existing guarded no-replace hard-link operation**, verifies both file checksum and *same-file identity* of the recorded copy and new final name, flushes again, and only then commits the **published** audit event chained to the earlier publishing receipt. If that file creation or the receipt commit fails, its state remains explicit and inspectable.
3. `inspect_manifest_publication(project, export_id)`: opens only the original strict read-only SQLite URI, verifies source/consent/stage/publication receipt integrity, checks the retained stage and any destination-side copy/final file's length, SHA-256 and final/copy physical identity, and returns a truthful state: `not_published`, `publishing_interrupted`, `publishing_copy_ready`, `awaiting_publication_receipt`, `published_verified`, or `published_previous_revision`. **A visible workbook without a completed published receipt is never reported as an audited success.**

The recorded copy and final hard link are in the same `exports/` filesystem, so the existing `Directory.publish_link` creates a new hardlink rather than assuming a cross-device rename is atomic. A pre-existing final file is never replaced or adopted, **even if its bytes exactly match** the staged workbook; only the exact registered copy and final filename with equal physical file identities can be reconciled after a lost response. A corrupt/modified partial destination copy is retained as evidence and refused. A previously published source revision remains a separately verifiable *historical artifact* if the research changes afterward; it is not relabelled as current or scientifically complete.

All public views preserve `global_unique_publications=null`, `source_retrieval_verified=false`, `deduplication_complete=false`, `verified_complete=false`. `audited_publication_success` means only that the specified staged artifact and a committed publication receipt match, **not** that the literature search or deduplication is complete. The recorded method is `provisional-manifest-publication/1`, distinct from the original strategy/count workbook journal. No new schema, credentials, network calls, model inference, renderer, external destination or provider text export is introduced.

## Verified and required failure scenarios

Offline original SQLite and actual Excel fixtures exercise publication after explicit approval, immutable original source/group rows, exact receipt count, safe project reopening and idempotent completion; termination after (a) publishing receipt with no file, (b) destination-side temporary copy, and (c) final hardlink before published receipt; rejection of unrelated but byte-identical final files; corruption of the destination-side copy without overwrite; source revision changes before publishing and between publishing intent and final hardlink; and historical published-artifact identification after later source changes.

Each user-visible/host-driven publication operation remains **disabled** until a later, separately reviewed GUI/worker integration with real researcher consent and current-revision reinspection. The existing strategy/count workbook export remains independent and unchanged. The completed initial product's full EXPORT-01, AT-18, archival recovery, and end-to-end AT-22 remain outstanding.
